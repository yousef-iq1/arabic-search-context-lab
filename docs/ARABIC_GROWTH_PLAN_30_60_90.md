# What I would do in the first 90 days

This is the plan I would start with if I joined the Arabic Developer Advocate role. I would expect it to change once I had access to real support questions, product data, and conversations with developers.

## First month

I would spend most of the first month learning.

- Read support questions and onboarding issues.
- See which docs and examples developers already use.
- Talk with Arabic-speaking developers in more than one country.
- Publish a small Arabic starting set: a quick start, a secure JavaScript/Next.js example, and a localization guide.
- Use Baghdad for in-person conversations because I already live here.

I would not assume one Arabic content strategy works the same way in Iraq, Saudi Arabia, Egypt, and Morocco.

## Second month

I would use what I learned to choose a few small experiments.

- Write around real developer problems, not generic brand topics.
- Run one online technical session.
- Keep a list of repeated questions.
- Talk with existing developer communities before asking for promotion or sponsorship.
- Turn at least one repeated problem into a docs, content, or product improvement.

## Third month

By the third month I should have enough signal to stop doing some things and repeat others.

- Keep the channels that bring real technical engagement.
- Stop activities that only create impressions.
- Build one repeatable format such as office hours, a workshop, or a small build challenge.
- Pick one use case that developers responded to and make a complete piece of content around it.
- Write a short review of what worked, what failed, and what I would change next.

## What I would measure

I would care about things such as:

- first successful API requests
- repeated technical questions
- completion of guides or examples
- follow-up from developers after a session
- feedback that becomes a real docs or product change
- technical conversations that continue after the first contact

## Baghdad and Iraqi Programmer Day

Baghdad is useful to me because I can talk to developers in person without travel.

If I attend Iraqi Programmer Day before being hired, I would go as myself. I would not present myself as a SerpApi representative.

I would use the event to ask practical questions about API use, search data, technical documentation, and what makes developers try or abandon a new service.

## What I can show before being hired

The work I can show now is already public:

- Arabic Search Context Lab
- the Arabic walkthrough
- an Arabic technical guide
- a localization sample
- notes from building with the API
- this 90-day plan

The point is not to pretend I already know the whole market. It is to show how I work when I need to learn a technical product and explain it to other developers.
